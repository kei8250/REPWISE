# Phase 1B-2b: 過去ワークアウトのコピー

## コピー規則

- コピー元は、未削除かつ完了済みのワークアウトに限定する。
- 新しいworkout、workout_exercise、workout_setには、それぞれ新しいUUIDを割り当てる。
- exercise_master ID、種目順、セット順、セット数、ワークアウト名は維持する。
- 種目メモはフォームや動作の注意点として再利用できるためコピーする。
- 全体メモ、評価、セットメモは前回固有の記録としてコピーしない。
- actual重量、actual rep、完了日時、完了状態はコピーせず、未実施状態から開始する。
- targetが設定済みなら、そのtargetをコピーする。
- target重量がない場合は前回のactual重量を初期target重量にする。
- target repの上下限がともにない場合は、前回のactual repを上下限の初期値にする。
- 上記は入力支援であり、次回目標生成やプログレッション判定ではない。

## 保存と同期

コピーはクライアントで新しいアクティブワークアウトのスナップショットを作り、既存のIndexedDB保存と`create` mutationへ渡す。専用の保存経路や同期APIは追加しない。

`source_workout_id`には直前のコピー元workout IDを保存する。コピーのコピーでも、実際に操作した直前の履歴を参照する。

サーバーは`create` mutationの適用時に、コピー元が同じ所有者の未削除・完了済みworkoutであることを再確認する。コピー元が削除された場合や存在しない場合は作成を拒否する。

多重操作はUIの同期ガードと処理中表示で抑止し、同一mutationの再送は既存の`processed_mutation`で冪等に処理する。

## 将来拡張

`source_workout_id`はテンプレートIDではない。Phase 1B-2bでは履歴間の由来だけを保持し、テンプレート、分析、次回目標生成は実装しない。
