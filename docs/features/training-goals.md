# 種目の長期目標と進捗

詳細分析の「目標を設定・進捗を見る」から `/goals` を開く。

- 種目ごとに目標重量・回数と期限を設定する。3か月・半年・1年の期限ボタンと日付指定に対応。
- 開始重量は指定回数以上の過去最高重量を仮入力し、変更可能。記録がなければ0kg。左右別種目は片側1回の重量基準。
- RM換算達成率は過去の完了済みセットの最大推定1RM ÷ 目標重量・目標回数の推定1RM × 100で計算する。開始値からの増加率ではない。実測達成は目標重量と回数の両方を満たす記録で別判定する。実績未取得・通信エラー時は進捗を表示しない。
- 月末の目安は開始値から期限までを日数で按分し、設定した増量幅で切り上げる。最終期限は目標値で固定。これは計画の目安であり、成長予測や強制的な増量指示ではない。
- 期限超過、残り重量・日数、達成、一時停止・再開、終了・復帰、編集、部位フィルターを用意。
- 1種目に管理中の目標は1件。終了した目標は残し、次の目標を作れる。

## 保存

この実装の目標はブラウザのlocalStorage `repwise-training-goals-v1` に保存する。サーバー保存や端末間の自動同期は行わない。同じ公開URLでもブラウザ・端末・オリジンが異なると別の保存領域となる。

JSON書き出し・読み込みでバックアップと引き継ぎが可能。同じIDは既存データを優先し、別IDの管理中目標が同じ種目に重複する場合は全体の読み込みを停止する。不正な保存データ・容量超過・競合時はエラーにし、保存成功と扱わない。別タブの変更は再読込し、更新日時が異なる同一目標への保存は拒否する。localStorageの同時書き込み自体はトランザクションではない。

トレーニング実績は既存の全期間分析APIから読み取り、完了・削除除外・左右別重量換算の既存ルールを利用する。フォーカス復帰や同期キューの変更時に実績を再取得する。DBの構造変更・migration・実ユーザー記録への書き込みは不要。

## 検証

`pnpm typecheck` / `pnpm lint` / `pnpm test` / `pnpm build`。

ブラウザではテスト用GET応答のみで375px・390pxを検証：登録、編集、再読込後の保持、一時停止・再開、終了・復帰、JSONバックアップ・別コンテキストへの取込、月末目安、回数条件を満たす達成判定、横はみ出しなし。実DB/APIへの書き込みは行わない。

## ホーム・記録との連携

PC・モバイルのメニューから「目標設定」を直接開ける。編集フォームは画面内のモーダルダイアログに表示し、保存できない理由もフォーム内に表示する。期限の3か月・半年・1年ボタンには選択状態があり、期限の日付を手入力すると解除される。

ホームは挑戦中を優先し、期限の近い管理中の目標を3件までカード表示する。目標回数に換算した現在重量、達成率、期限・残り日数を表示し、カレンダーより上に配置する。全件は目標設定へ移動する。期間集計（直近7日・30日）、前回のトレーニング、重複する履歴カードはホームから除去。履歴へのメニューとカレンダーは維持する。

記録画面では目標のある種目に限り保存済み進捗、目標までの残り重量、月末の目安を表示する。今回の完了済みセットは別の「保存前の見込み」として計算し、保存済み達成率とは混ぜない。左右別では片側重量と少ない方の回数を使う。目標変更・フォーカス復帰・同期キュー変更時に表示を更新する。これらの表示処理は目標も実績も書き換えない。


## RM換算達成率と記録画面の換算表

最新版 `1328157` に機能を追加。旧チャットのコミット・差分は使用しない。

採用したのは種目別の簡易換算式（係数40 / 33.3）。推定値であり、全競技共通の公式表ではない。

- ベンチ：推定1RM = 重量 × (1 + 回数 / 40)
- スクワット・デッドリフト：推定1RM = 重量 × (1 + 回数 / 33.3)
- 1回の実測はその重量を1RMとして使う。式で増幅しない。
- 対象は正の重量、整数1〜12回。13回以上は外挿しない。既存の13〜100回の目標・記録は維持し、換算対象外と表示。実測達成は別に評価できる。
- 任意回数への逆算重量 = 推定1RM / (1 + 回数 / 係数)。1回の逆算は推定1RMそのもの。

例：ベンチ60kg×8回は72kg、目標80kg×8回は96kgの推定1RMになるため、達成率は72 / 96 × 100 = 75%。開始重量50kgからの増加率33%とは別の意味である。目標80kg×1回なら分母は80kgとなり90%。目標回数も必ず分母に含める。

ホーム・目標設定・記録入力は同一の `goalProgress` と `rm.ts` を使用する。選択式、計算に使った実績日・重量・回数、分子・分母を画面に表示。換算上100%を超える場合は割合をそのまま表示し、バーだけ100%に収める。換算上の到達と、実測での重量・回数目標達成は分離する。例：75kg×12回は97.5kgの推定1RMで目標80kg×8回の96kgを超えるが、実測80kg×8回達成とは表示しない。

過去に換算可能な実績がない場合は、手入力の開始値から割合を捏造せず「換算データなし」。開始値は引き続き月別計画に使用する。月末の残り重量は現在の推定1RMを目標回数へ逆算した重量との差であり、その旨を表示する。換算がない場合は開始値からの計画と明記する。

既存目標の保存形式version 1を維持し、任意の `rmMethod` だけ追加。未指定なら目標名にベンチ/benchを含む場合はベンチ、それ以外はスクワット・デッドリフト方式。表示だけでは保存し直さない。目標編集で方式を明示選択できる。他種目への適用は参考値。詳細分析の既存e1RM・PR計算（Epley、係数30）は変更しない。

記録画面の「RM換算表を見る」は保存済み目標の方式を初期選択する（目標がなければ種目名で選択）。ダイアログ内で方式・重量・回数を切り替え、1〜12回の逆算重量と1RM比を一覧表示する。表の操作は独立したReact stateに限り、記録・目標への保存処理やonChangeを呼ばない。今回分を含む進捗は引き続き保存前の見込みとして区別する。

高回数のセットに同じ重量の8回セットが隠れないよう、分析レスポンスには既存repTrendを維持したまま換算可能なセット `rmRepTrend` を併載する。DBや既存記録への書き込みは不要。


## 過去記録と目標日の表示

目標作成前の記録も含む、今日までの有効な全記録をRM換算・実測達成の対象とする。開始日は月別計画の起点だけに使用する。未来日・削除済み・未完了セットは除外する既存ルールを維持する。

スクワット用の例：160kg×3回は推定1RM174.4144kg。目標180kg×1回なら96.9%。目標170kg×5回なら、現在の推定5回重量は151.6449kg、達成率89.2%。ホーム・目標設定・入力中の進捗は同一の関数と換算方式を使用する。

カレンダーは保存済み目標を独立して読み取り、管理中の目標日を黄色い点で表示する。記録のない未来日も選択でき、同日がトレーニング日なら両方を保持する。目標と記録が重なる日はダイアログで両方を選べる。次の目標日の月に移動するボタンと、表示月の目標日一覧を用意。目標日の変更や終了は既存の保存イベント・別タブ同期で追従する。

メニューはホーム・記録・目標設定・詳細分析を主要導線とし、履歴・設定はPCでは「管理・振り返り」、モバイルでは「その他」にまとめる。履歴・設定へのアクセスは維持する。
