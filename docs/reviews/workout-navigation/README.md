# 削除済み記録・読み込み失敗画面・カレンダーの導線

## 修正前と修正後

| 場所 | 修正前 | 修正後 |
| --- | --- | --- |
| 設定の同期一覧 | 削除済みの下書きも通常の同期失敗として表示し、開けない記録へのリンクを表示 | 通常の未同期記録と「削除の反映待ち」を分離。削除済みへのリンクは出さず、反映の再試行を提供 |
| 削除反映の完了 | 表示上、保存失敗と削除待ちを区別できない | 削除がサーバーで確認されてキューから消えると反映待ち表示も消える |
| 記録画面の読み込み失敗 | activeModeで全体のナビゲーションを隠し、再試行のみ表示 | 通常のナビゲーションを記録中・読み込み中・失敗時・終了済みの全状態に表示。端末で削除済みならその理由を表示 |
| スマートフォンのナビゲーション | 詳細分析はホーム経由 | 「ホーム・記録する・履歴・設定・詳細分析」の5項目を常設 |
| ホームのカレンダー | 日付から履歴の検索画面へ移動 | 1件の日はその記録の詳細へ直接移動。複数件の日は日付内の一覧から選んで直接移動 |

履歴画面が渡す `onSelectDate` による日付絞り込みは維持。ホームでは記録のない日を無効化し、記録を取得できない場合は再取得と端末内の記録の参照を提供する。複数件の選択はダイアログで開き、Escapeまたは「カレンダーへ戻る」で閉じると元の日付にフォーカスを戻す。

削除待ちの先頭に古い保存失敗が残っていても、最新の端末の状態で表示を分類する。削除待ちを隠すために未送信の変更を捨てることはしない。キューの順序・内容・競合の扱い・atomic claim・ACK処理は変更していない。削除を取り消した記録は通常の同期一覧に戻る。

## 検証

- `pnpm typecheck` 成功
- `pnpm lint` 成功
- `pnpm test` 成功：31ファイル、315テスト
- `pnpm build` 成功：既存のproxy検出・ルート静的分類の案内あり
- Chromiumの375px・390px幅でタッチ操作を検証。横スクロールなし。記録画面からのナビゲーション、削除済み・404画面からの記録／分析／履歴への移動、削除反映の再試行と一覧からの消失、カレンダーの単一・複数記録の直接遷移、Escape後のフォーカス復帰を確認
- 既存のブラウザー検証も再実行：入力途中の全期間一覧、スワイプ／キーボード削除と取り消し、末尾ページの削除、左右別種目の作成・入力・修正・終了・履歴・同期を確認

自動回帰テストは削除前の保存失敗と削除の分類、取り消し後の分類、下書きがないキューの分類、競合時の表示、選択日の記録の抽出と順序、記録ページ全体に残るナビゲーションを追加した。

ブラウザーのAPIはすべて合成データで置き換え、専用プロファイルのlocalhostのIndexedDBのみ使用。公開サイト・実ユーザーの記録・D1・Cloudflare APIは操作していない。マージ・デプロイ・migration適用も行っていない。本変更で新たなDBスキーマ変更はない。PRは未マージのPR #6の上に積んでいる。

## 検証の再実行

ローカル開発サーバーを3000番、専用のChromiumデバッグプロファイルを9223番で起動して実行する。カレンダーの合成記録は2026年10月を対象としている。

```sh
node scripts/review-draft-cleanup-side-reps.mjs --navigation
# 既存フローの検証画像は別ディレクトリへ保存する
mkdir -p /tmp/repwise-navigation-regression
REPWISE_REVIEW_OUTPUT_DIR=/tmp/repwise-navigation-regression node scripts/review-draft-cleanup-side-reps.mjs
```

このスクリプトは専用ブラウザープロファイル内のlocalhost:3000の保存領域を初期化する。普段使いのブラウザーでは実行しない。

## 残る制約

実機のソフトウェアキーボードやSafariでの確認は未実施。通信障害・認証エラー・version競合そのものを解消する変更ではなく、削除が未反映ならその状態は別枠に残す。競合を自動で上書きすることはない。公開サイトへの反映には既存のレビュー・リリース手順が必要。
