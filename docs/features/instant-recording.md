# 入力した時点で記録する

「記録する」から日付を選び、種目と実績を入力する。終了・確定操作は不要。重量と回数が有効なセットを自動でその日の記録として扱い、履歴・カレンダー・目標達成率に反映する。編集は記録詳細の「編集」から同じ自動保存画面を開く。削除は従来の削除機能を使用する。

## 保存と互換性

- DB構造・migrationは変更しない。新しい記録は既存の `completed` 状態でcreateし、その後はversion付きのedit操作を使う。既存クライアントのactive/create/complete操作も引き続き受け付ける。
- 入力の一部（重量だけ、左右片方だけなど）も端末とサーバーに保存する。有効な重量・回数が揃ったセットだけcompletedへ正規化する。それ以外の値を勝手に補完・削除せず、集計には入れない。セットが1件も揃っていない空記録は履歴・カレンダーには表示しない。
- 即時保存のeditはローカルでもcompletedとし、手動保存式の旧completed_edit/editBaselineとは区別する。キューのFIFO、再送の冪等性、baseVersionの競合検出、削除済み保護を維持する。
- 画面内で最新の値を保持し、全スナップショットのIndexedDBトランザクションを即時に開始する。通信失敗中も端末の記録を再表示し、同期失敗と端末保存失敗を区別する。サーバー同期は既存の待機時間・再送ルールを維持する。
- 目標計算はサーバー実績に同期前の端末保存済み記録を重ねる。同じworkout IDの古い実績は置き換え、二重加算しない。旧手動編集の未保存内容は含めない。
- ホームと履歴に「入力途中」の表示・分類・再開導線を置かない。既存active記録の一括削除やDB更新は今回実行しない。過去の実績と目標は保持する。

## 表示

記録画面ではセットの完了ボタン・種目の完了ボタン・トレーニング終了の確認を使わない。入力欄は自動保存で折りたたまず、そのまま編集できる。「記録を確認」は保存済みの詳細を開くだけで、記録の成立条件ではない。

目標の進捗バーはグレーの未達領域と濃い緑の達成領域に分け、右端に境界線と「目標100%」を表示する。割合が100%を超えた場合は、既存ルールどおり数値はそのまま、バーだけ100%に収める。

主要画面の「ワークアウト」を「トレーニング」に統一し、「rep」を入力欄では「回数」と表記。「目標の○回換算で」は「○回できる重量の目安」に変更する。
