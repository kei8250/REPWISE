## 修正前後

| 報告 | 原因と修正 |
| --- | --- |
| 前回実績があるのに概要は「参考記録なし」 | 概要は種目全体の進行判定から表示、セット欄は役割・位置・重量基準の合う有効実績から表示していた。概要もセット欄と同じ `referenceForSet` を使い、「セット別の前回実績を参照中」と参照可能数を表示。不一致・取得失敗・読み込み中も区別。自動提案用の判定対象は別のラベルにした |
| 種目検索0件で「この期間の記録なし」 | 期間と検索条件を区別していなかった。種目/部位の条件がある場合は「指定した種目・部位に一致する記録がありません」。条件クリアで名前・部位の入力とURLを解除し、月・日付・完了状態は維持 |
| 分析期間が再読込で30日に戻る | コンポーネント内のstateのみだった。`range=7d/30d/90d/all` をURLに保持し、再読み込み・共有リンク・popstateで復元。既存exerciseId等のパラメータは保持。不正な値は30日にフォールバック |
| 完了記録の主要操作まで長いスクロール | 操作が判定と全セットの下にあった。「同じメニューで開始」「編集」「削除」を評価・セットより上に移動。削除確認ダイアログは維持。判定の根拠・ルールは折りたたみ、表示したいときに展開できる。375/390pxでスクロールなしに主要操作を確認 |
| 完了記録でreps/回が混在 | 目標欄だけrepsがハードコードされていた。「回」へ統一 |

保存・同期・進行ルール・DB/API契約・依存関係は変更していない。
