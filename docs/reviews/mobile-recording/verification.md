# スマホの種目選択・記録開始の修正検証

対象ブランチ: `fix/history-without-deleted-records`。修正開始時のHEADは `1b438fb53bc5026a0831986db01f9698b8f72878`、作業ツリーはクリーン。リポジトリ内と親ディレクトリに適用対象のAGENTS.mdはなかった。

## 原因と対応

- 種目選択: DialogContentの暗黙グリッド行が内容の高さまで広がり、内側のoverflow-y:autoに高さ制約がなかった。外側を表示領域の88%の高さ、行を`auto minmax(0,1fr)`にし、内側に`min-height:0`を指定。ヘッダー・閉じるボタンは残し、一覧と作成フォームを一緒にスクロールする。モバイルのキーボードに備えVisualViewportの高さ・位置の変化にも追従し、リスナーを閉じる際に解除する。
- 長い名前: Buttonのwhite-space:nowrapを解除し、テキストとグリッドの最小幅を0にした。スマホは1列、全文を折り返して表示し、追加・選択済みアイコンは縮ませない。
- 記録開始: 「種目を選ぶ」で保存・遷移せず直接一覧を開く。最初の種目が選ばれた時点でその種目を含む記録を作成する。二重作成を防止する。中止しても名前・日付を保持する。既存の記録・メモを削除する処理は追加していない。
- 共通実装の確認: 記録入力と既存記録編集のExercisePickerは今回の修正を共用する。カレンダーのDialogContent、目標編集とRM換算のネイティブdialogは外側自身が高さ制限付きでスクロールする構成で、同じ内側グリッドの問題はなかった。CommandDialogは現在アプリ画面から未使用。

## 操作回帰テスト

`scripts/browser/exercise-picker.mjs`。ローカルの開発サーバーに対し、全APIをPlaywrightでインターセプトする。実ユーザーの記録・目標・DBにはアクセスしない。Playwrightは既存の一時ディレクトリのものを使用し、アプリの依存関係やlockfileは変更していない。

実行例（別ターミナルで`pnpm dev --host 127.0.0.1 --port 3010`を起動）:

```sh
REPWISE_PLAYWRIGHT_MODULE=/tmp/repwise-browser/node_modules/playwright node scripts/browser/exercise-picker.mjs
```

Playwrightが通常のモジュール解決で利用できる場合、環境変数は不要。Chromiumのパスは`CHROMIUM_PATH`、ローカルサーバーURLは`REPWISE_TEST_ORIGIN`で指定可能。

修正前:

- `REPWISE_TEST_CASE=scroll`で旧導線から一覧を開き、全4幅でスクロール領域のclientHeight=scrollHeight=5,054pxとなり失敗した。
- 通常モードで「種目を選ぶ」を押すと直接一覧が開かず、先に記録画面へ遷移するため全4幅で失敗した。

修正後: Chromiumのタッチエミュレーションで320/375/390/430px、初期高さ568px、縮小高さ360pxで全ケース成功。

- 65種目の一覧をカード上から実際に縦スワイプし、スクロール位置が変化し、種目が誤追加されない。
- 部位タブを横スワイプでき、一覧の縦スクロールに干渉しない。
- 長い正式名がカード内で折り返される。
- 末尾の作成フォームにスクロールして入力・操作できる。
- 選択せず閉じた場合、APIへの記録保存がなく、IndexedDBの記録・送信待ちキューも0件。フォームの名前を保持し、背景の縦スクロールが復帰する。
- 再オープン、検索、該当なし、部位絞り込みを操作できる。
- 高さ360pxで検索後に末尾の種目をクリックできる。
- 記録画面から再び一覧を開き、VisualViewportの高さ240px・offsetTop45pxを模擬してもダイアログが可視領域に収まる。新規種目のフォームまでスクロールし「作成して追加」を実際にクリックできる。
- 種目追加後、元の種目の重量60kg・回数8回とトレーニング全体のメモが保持される。
- ページ内の横はみ出し・JavaScript例外なし。
